# 学习笔记：给大肥鱼加动作、物理摆动、视线跟随

> 阶段：**只研究，不施工**（`_probe/` 里的勘察脚本除外）。所有结论都是本机实测：`_probe/pose.mjs` 摆姿势/播动作截图 + 直接读回引擎里的参数值。
> 素材：`大肥鱼`（moc3 v5 / Cubism 5），模型包放在 `assets/model/`（自备，不入库）。

---

## 0. 六条结论（先看这个）

1. **新动作不需要 Cubism Editor，也不需要 cmo3**：`motion3.json` 是纯参数关键帧，手写即可，我们已有解码/校验器和 8 个原始动作当模板。
2. **动作里要写的是 OP 参数**（`AngleX/AngleY/AngleZ`、`PositionX/Y/Z`、`LeanInput`）**+ 自由参数**（手臂链、`key*`、`Clothes*`、眼/嘴）。OP → 姿态是物理算出来的，比例近似 1:1。
3. **动作里直接写 `ParamAngle*` 是无效的**（实测：手写 nod 动作写 `ParamAngleY`，播放全程读回 0）——这些是物理输出参数，会被物理覆盖。
4. **"动作自带物理摆动"是免费的**：物理在动作之后读参数，头发/尾巴/裙摆会滞后摆动（实测 `LateHairX1` 在 0.25~0.34 间持续摆动，`FrontHairY4` −0.28→0.25→−0.07 反复过零）。
5. **`setParameterValueById()` 只影响最终渲染，物理看不见**（`loadParameters` 每帧先恢复"上一帧动作更新后"的快照）⇒ 用它做的转头（视线跟随、拖拽惯性）**不会**带动头发。这是本次最重要的坑。
6. 引擎自带 `Config.MouseFollow` 对本模型失效（写的是被物理覆盖的 `ParamAngleX`）；视线跟随要用覆盖表自己写，并接受"头发不跟"这个取舍，或改用"播放一段摆动动作"来实现惯性。

## 1. 引擎每帧到底发生了什么（决定了上面的一切）

`node_modules/easy-live2d/dist/index.js` 的 `update(deltaTime)`（约 17013–17052）：

```
1. _dragManager.update(dt)
2. _model.loadParameters()        ← 恢复"上一帧 saveParameters 时"的快照
3. motionCtrl.update()            ← 动作写参数（会覆盖快照）
   _motionManager.updateMotion()
4. _model.saveParameters()        ← 快照 = 动作之后、物理之前
5. _expressionManager.updateMotion()
6. effectCtrl.updateEffects()
7. _pose.updateParameters()
8. _physics.evaluate(model, dt)   ← 物理读取当前参数值（含动作输出），写回姿态参数
9. _applyParameterOverrides()     ← 我们 setParameterValueById 的值，最后覆盖
10. _model.update()
```

由此推出三条硬结论：

| 写入方式 | 物理能看到吗 | 能产生姿势吗 | 带头发摆动吗 |
|---|---|---|---|
| `motion3` 写 OP 参数 | ✅（快照里） | ✅ 物理转换 | ✅ 自动（物理上游变化） |
| `motion3` 写 `ParamAngleX/Y/Z` | ✅（快照里） | ❌ 被物理覆盖成 0 | ❌ |
| `setParameterValueById('ParamAngleZ', …)` | ❌（在物理之后） | ✅ 渲染出来 | ❌（物理读到 0） |
| `setParameterValueById('FrontHairX*', …)` | ❌ | — | ✅ 直接改渲染（我们的二次运动层就用这个） |

物理本身：131 组、299 输入、292 输出、`Fps: 60`，固定步长 `physicsDeltaTime = 1/60` 子步进 ⇒ **窗口降到 15fps，摆动速度不变**，只是插值粗。

## 2. 怎么造新动作（motion3.json 手写）

### 2.1 文件结构（已用 8 个原始动作 8/8 校验通过）

```jsonc
{
  "Version": 3,
  "Meta": {
    "Duration": 1.2, "Fps": 60, "Loop": false,
    "FadeInTime": 0.25, "FadeOutTime": 0.35,
    "AreBeziersRestricted": true,
    "CurveCount": 3, "TotalSegmentCount": 12, "TotalPointCount": 26
  },
  "Curves": [
    { "Target": "Parameter", "Id": "AngleZ",
      "Segments": [0, 0, 0, 0.25, 20, 0, 0.9, 24, 0, 1.2, 0] }
  ]
}
```

`Segments` 编码：开头 `[t0, v0]` 是起点，之后循环 `[type, 点…]`：

| type | 含义 | 段内点数 |
|---|---|---|
| `0` | 线性 | 1 个 `(t, v)` |
| `1` | 三次贝塞尔 | 3 个：P1、P2、P3 |
| `2` | 阶梯 | 1 个 |
| `3` | 逆阶梯 | 1 个 |

- 贝塞尔控制点 t 是**强制**的：`P1.t = (P3.t−P0.t)/3`、`P2.t = 2(P3.t−P0.t)/3`，只有 v 自由。
- **三个计数必须自洽**：`CurveCount` = 曲线数，`TotalSegmentCount` = Σ段数，`TotalPointCount` = Σ(段数+1)。我第一次写错（25 vs 18），引擎报 MISMATCH——虽然只是 warning，但动作会表现异常；现在 `_probe/motion-decode.mjs` 会逐条核。
- 建议：**全部用 type 0 线性 + 密一点的点**（每 0.05–0.1s 一个），肉眼与贝塞尔无差，且不会算错。
- `Duration` 是秒，`Fps` 写 60（引擎按 60 采样没影响）。

### 2.2 参数清单：动作里该写什么

**✅ 姿态：写 OP 参数（物理会把它变成姿势，并顺带甩头发）**

| 想要 | 写这个 | 幅度 | 实测映射 |
|---|---|---|---|
| 左右转头 | `AngleX` | ±30 | `AngleY 10 → ParamAngleY 10.67`；`20 → 21.33`；`30 → 30`（夹到上限），**约 1:1** |
| 抬头/低头 | `AngleY` | ±30 | 同上；`+` = 抬头（`ParamAngleY+`） |
| 歪头 | `AngleZ` | ±30 | `AngleZ 20 → ParamAngleZ 18.7` |
| 身体扭转 | `PositionX` | ±30 | `PositionX 20 → ParamBodyAngleX 20.00`（1:1） |
| 前倾/后仰 | `PositionY`（+`LeanInput`） | ±30 | 组名「身体Y」：PositionY+Breath+Lean → `ParamBodyAngleY` |
| 侧倾 | `PositionZ`（+`PositionX`） | ±30 | 组名「身体Z」→ `ParamBodyAngleZ` |

- 待机呼吸：`ParamBreath`。

**❌ 不要写**：`ParamAngleX/Y/Z`、`ParamBodyAngle*`、`HipAngle*`、`LArm/RArm/...`、`FrontHair*`、`LateHair*`、`SideHair*`、`Skirt*`、`Param_Angle_Rotation84..89`、`Hat_*`——这些全是物理输出，写了要么被覆盖，要么和物理打架。

## 3. 物理：免费的摆动从哪来

### 3.1 结构

- 131 组摆锤；输入类型只有「位置X / 位置Y / 角度」；输出有倍率/影响程度/翻转。
- 关键链路（组名 → 输入 → 输出）：
  - `OX/OY/OZ`：`AngleX/Y/Z` → `ParamAngleX/Y/Z`（×28/32/28）
  - `身体X`：`PositionX` → `ParamBodyAngleX`（×30）；`身体Y`：`PositionY+Breath+Lean` → `ParamBodyAngleY`；`身体Z`：`PositionZ+PositionX` → `ParamBodyAngleZ`；`Positon`：→ `ParamBodyAngleRX`
  - `前发X`：`ParamAngleX`+`ParamAngleZ` → `FrontHairX1..4`；`前发Y`：`ParamAngleY` → `FrontHairY1..4`
  - `后发X/Y`：→ `LateHairX1..5 / LateHairY1..5`；`侧发R/L/X/Y`；`短后发`；`帽子X/Y`；`头配饰`
  - `尾巴`：`ParamBodyAngleX/Z + Breath + Lean + Clothes2` → `Param_Angle_Rotation84..89`（7 段长链）
  - `裙子X/Y`、`裙子层级X/Y`、`左右袖子X/Y`、`左右飘带`、`胸X/Y`、`兽耳`（`ParamBrow`→`Control`→`LEar/REar`）

### 3.2 实测数据（决定性）

| 输入（通过 motion） | 读回 | 说明 |
|---|---|---|
| `AngleY = 10 / 20 / 30` | `ParamAngleY = 10.67 / 21.33 / 30.00` | 近似 1:1，超过 30 被夹 |
| `AngleZ = 20` | `ParamAngleZ = 18.7` | 同上 |
| `PositionX = 20` | `ParamBodyAngleX = 20.00` | 1:1 |
| 上述同时 | `LateHairX1 = 0.23~0.34`、`FrontHairY4 = −0.28→0.25→−0.07` | **头发在持续摆动**（物理滞后 + 过零） |
| `ParamAngleZ = 20` 用 `setParameterValueById` | `ParamAngleZ = 20`（渲染生效），但 `LateHairX1 ≈ 0`，头部物理不再摆动 | 覆盖表物理看不见 |
| 手写 motion 写 `ParamAngleY` | 读回 0（全程） | 物理覆盖，动作无效 |

⇒ **只要动作是"motion 写 OP 参数"这条路，物理摆动就是白送的**；用覆盖表写 `ParamAngle*` 只是"硬摆头"，不带摆动。

### 3.3 极限值（实测不会破图，但会用坏）

`FrontHairX*` 1.0、`SideHairX*` 1.0、`LateHairX*` 0.9、`SkirtX*` ±0.9、`Param_Angle_Rotation*` 45 都能正常渲染不撕裂；但尾巴写 30 以上会绕到身前、发丝写满会显得"被风一直吹"。**建议二次运动层 clamp：前发 ±0.6、侧发 ±0.7、后发 ±0.9、裙摆 ±0.7、尾巴 ±15°**。

## 4. 二次运动层（补物理的短板，未施工）

### 4.1 为什么需要

- 物理只对"动作驱动的 OP 变化"有反应；**视线跟随、拖拽惯性这些用覆盖表写 `ParamAngle*` 的变化，物理完全看不到**。
- 物理本身幅度也小（`LateHairX1` 0.25 就是上限量级），拖窗口时头发几乎不动。

### 4.2 模型：每条链一个二阶阻尼振子

```
target = -K * dθ/dt                          // 角速度 → 惯性反向偏转
v += (-stiffness * (x - target) - damping * v) * dt
x += v * dt
x = clamp(x, -limit, limit)
```

- `dθ/dt` 取"本帧 `ParamAngleX/Y/Z` 与上一帧之差 / dt"，拖窗口时把窗口速度换算成同样的角速度喂进来。
- `stiffness`：头发 55–75、尾巴 25–35、裙子 40；`damping ≈ 0.55~0.7 × 2√stiffness`（尾巴取 0.45×，甩得更久）。
- 沿链递减系数（顶端 0.4 → 末端 1.0），模拟发梢甩得更开。

| 链 | 写这些参数 | 系数 | stiffness / damping | 驱动源 |
|---|---|---|---|---|
| 前发 | `FrontHairX1..4` | 0.45 / 0.7 / 0.9 / 1.0 | 65 / 0.62 | `ParamAngleZ` + 0.6×`ParamAngleX` |
| 后发 | `LateHairX1..5` | 0.3 / 0.5 / 0.7 / 0.9 / 1.0 | 45 / 0.55 | 同上 ×1.5 |
| 侧发 | `SideHairRX1..3`、`SideHairX1..3` | 0.5 / 0.75 / 1.0 | 60 / 0.6 | `ParamAngleX` ×1.2 |
| 尾巴 | `Param_Angle_Rotation84..89` | 0.25→1.0（量纲 ×15） | 28 / 0.45 | `ParamBodyAngleZ` + 窗口速度 |
| 裙摆 | `SkirtX1..4` | 0.4 / 0.7 / 0.9 / 1.0 | 40 / 0.6 | `ParamBodyAngleX` + `HipAngleX` |
| 袖子 | `LSleeveX1..3` / `RSleeveX1..3` | 0.6 / 0.8 / 1.0 | 50 / 0.65 | `ParamBodyAngleX` |
| 飘带 | `LRibbonX1..4` / `RRibbonX1..4` | 0.4 / 0.65 / 0.85 / 1.0 | 35 / 0.5 | `ParamBodyAngleX` + 窗口速度 |
| 帽子 | `Hat_XA..XC` | 0.5 / 0.8 / 1.0 | 70 / 0.7 | `ParamAngleZ` |

> 每帧最多写 ~35 个参数，开销可忽略；关闭时 60ms 内平滑归零。

### 4.3 拖拽惯性

- 拖动时记录窗口速度 `vx, vy`（2 帧平均）。
- 拖动中：`ParamBodyAngleZ = clamp(−vx × 0.012, ±12)`、`ParamBodyAngleY = clamp(vy × 0.008, ±8)`、`ParamAngleZ = clamp(−vx × 0.008, ±10)`（整只被拽着走的滞后感）。
- **松手**：把当前偏转当振子初值、速度当冲量 → 2–3 次过零余摆后回正。
- 想更"物理"，可选做法：松手时播一段 0.6s 的 `AxisSway` 动作（动画写 `AngleX/AngleZ` 振荡）→ 走真物理，头发尾巴一起甩；缺点是会和 idle 抢动作槽。

## 5. 视线跟随鼠标（可关）

- 引擎自带 `MouseFollow` 对本模型无效（写 `ParamAngleX`，被物理覆盖），关掉它，自己写覆盖表。
- 输入：窗口内 `pointermove`；点击穿透模式下用主进程 `screen.getCursorScreenPoint()` 30Hz 轮询 + IPC。
- 映射：`nx = clamp((x−cx)/(w/2), −1, 1)`；头 `ParamAngleX = nx×20`、`ParamAngleY = ny×14`（一阶平滑 τ=120ms）；眼 `ParamEyeBallX = nx×0.8`、`ParamEyeBallY = ny×0.65`（τ=60ms）。
- 死区 8px；鼠标离开窗口/1.5s 不动 → 100ms 内平滑回 0。
- **与动作冲突**：动作播放期间暂停头部跟随（否则每帧覆盖会把动作的转头抹掉），只留眼球；动作结束后 200ms 淡入。
- 已知取舍：这种方式转头**不会带动头发**（§1 表）。要带，就在转头时同时给二次运动层喂一个冲量。
- 开关存 `state.json`，快捷键 `Ctrl+Shift+M`。

## 7. 验收清单

1. `?pose=` 勘察模式仍可用。
2. 新动作：`?motion=Gesture/nod` 三帧拼图，姿态连贯；日志里 `ParamAngleY` 有非零值。
3. 动作自带摆动：`?motion=Gesture/hop` 期间 `LateHairX1` 非零、结束后 1s 内衰减。
4. 二次运动层：拖窗口 300px 松手，`ParamBodyAngleZ` 出现 2–3 次过零。
5. 视线跟随：四角 `ParamAngleX/Y` 到 ±20/±14，关掉回 0；动作期间不被抹。
6. 后台 15fps：物理摆动速度不变。
7. `PET_CHECK=1` 自检全绿；显存仍 ≤ 80MB。

## 8. 风险

- **别在 motion3 里写 `ParamAngle*`/`ParamBodyAngle*`/头发裙子尾巴参数**——会静默失效或和物理打架。
- 覆盖表写的姿态**不进入物理**，所以"硬转头"不会有头发跟随，别误以为是 bug。
- 尾巴 `Param_Angle_Rotation*` 超过 ±25° 会绕到身前；发丝写满会像被风一直吹。
- 表情走 expression 是 1s 淡入；要"瞬间惊讶"就写 `key5` 参数并自己做过渡。
- `Escape` 这类长动作（13s）要检查 `FadeOutTime`，否则接 idle 会跳。
