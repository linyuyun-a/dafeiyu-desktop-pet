# 三个参考项目对这个桌宠意味着什么

调研日期 2026-11-09。三个仓库都 clone 在 `_probe/refs/`，全部 MIT（模型本身仍归原作者，不能分发）。

| 项目 | 形态 | 能不能当底座 |
|---|---|---|
| **fulaska / 大肥鱼 Live2D 桌宠** | Electron + Pixi8 + `untitled-pixi-live2d-engine`，同一个「大肥鱼」模型，透明窗、分区互动、生命层、设置窗、打包 | **能**。引擎/分层/热区三块是真货 |
| **petbox / whale-pet-shell** | Electron 壳 + 鲸语网页舞台，控制面是一堆本地 HTTP 路由 | 只能拆零件（穿透、mood、面板） |
| **jingyu / 鲸语** | Python 服务 + web 舞台，自然语言→动作计划 IR→编译 | 只能借思路（IR+编译器） |

三家的共同短板：**都没有"大脑"**。fulaska 只把外部 `status.json` 演成气泡；petbox 把回话 POST 给外部 bridge；
jingyu 只是一个动作编译服务。我们那套「云端 AstrBot（SSE）→ 语义标记 → 动作/表情」是他们都没有的。

---

## 1. fulaska：唯一值得当底座的

**真货（可直接搬）**

- `src/stage/pose-bus.js`（~72 行）：解决本模型最硬的坑——`ParamAngle*/ParamBodyAngle*` **既入又出**。
  每帧首次 `add` 记 base（含待机摆动），最终 `clamp(base+delta)`，物理前 flush 一次（喂物理）、物理后 flush 一次（决定画面）。
  我们现在的做法是「干脆不写这些参数」，代价是**真转头做不出来**。
- 两个写点：`onBeforePhysics`（物理输入：Angle*、Position*、LeanInput、Clothes*、Movement*）与
  `onBeforeUpdate`（表情/生命层）。`src/stage/engine.js` 里 `physics.evaluate` 被包了一层。
  我们项目里 `setParameterValueById` 写在物理之后，所以 `LeanInput` 类参数**物理看不见**（坑 7 就是这么来的）。
- `src/stage/layers.js`：L0–L5 分层（待机/视线/表情/动作/互动/Agent），后写覆盖先写，退出显式复位。
  我们用的是「谁最后写谁赢」的隐式约定。
- `src/stage/regions/{geometry,input,store}.js`：多边形热区 + z 序 + holes 差集 + 按下时 alpha 采样；
  手势阈值按画布宽比例（tap ≤2% 且 ≤420ms / pet 每 3% 一步 / drag >8%），起手可在区外滑入后采纳。
  我们现在只有两个矩形 `zoneAt()`。
- `app/main.mjs` + `app/settings.*`：22 项设置存 `userData/settings.json`，设置是**独立窗口**，
  主进程广播、渲染单向 apply（防回环）；`scripts/pack.mjs` 用 electron-packager 出「完整版 + 无模型版」。
- 生命层：`life.js`（眨眼 2.4–5.6s，18% 连眨，乘在表情之后）、`capture.js`（ParamBreath 0.19Hz，物理前）、
  `mouth.js`（说话假口型）、`idle-motions.js`（8–18s 一段，首尾归零 + 钟形包络）、`face-pinch.js`、`tickle.js`。

**壳（别当真）**：`agent-link.js` 只是把 `status.json` 映射成表情+气泡；`app/editor.js` 671 行没接主循环；
`contracts.ts` 里 motion/animation/param 分支未实现；服务端没有真抢占（`interrupted` 恒 null）；**零测试**。

**已验证**：把它 clone 下来 `npm i`、把我们的 `live2dcubismcore.min.js` 放进 `vendor/`，
用 `node scripts/serve.mjs --model "…/assets/model/model3.json"` 可以直接解析我们的模型：
`params 509 / parts 147 / motions 44 / expressions 46`，热区自动铺出 7 块（头/胸/腰/裙摆/腿/脚/尾巴）。
（无头 Edge + swiftshader 下画面不渲染，但官方样例 Hiyori 同样不渲染 ⇒ 是环境问题，不是模型不兼容。）

## 2. petbox：拆零件

- **像素级穿透**最值得抄：preload 里 `readPixels` 读光标处 alpha（>12 算命中），
  失败退化成补丁写入的 `#scene.dataset.hit` 矩形外扩 4px；同帧 16ms、同 3px 格 120ms 缓存；
  主进程 `setIgnoreMouseEvents(ignore,{forward:true})`。
- **设置面板**是 396×760 原生 HTML/CSS 独立窗（无框架无构建）：尺寸滑杆 420–1400、帧率 30/60/90/0–240、
  路径配置、状态行；即时开关放右键菜单。
- **亲密度**：`touch-stats.json` `{total, zoneTotal, days{}, lastTouchAt, firstAt}`，保留 60 天；
  等级阈值 `[1,40,150,450,1200,3000]`；连击阈值 3/4/5；6 小时没摸→惊；当天 15 下→黏。
- **mood 引擎**（`bridge/dsh-pet-bridge/lib/mood/*`，纯函数 + 17 个 `node --test`）：半衰期衰减账本、
  规则 DSL、带 TTL 的「此刻」层、主动开口 burst、原子写 + 坏文件自愈。
- **阶段气泡** `/tick`：最多 5 颗、2–4s、头顶下 6%–46% 随机行、75% 落外侧避开正脸、与旧泡重叠重抽 ≤7 次。

## 3. jingyu：借思路

- 计划 IR：`{version,title,intent,summary,view,actions[]}`，11 种动作
  （trajectory/look/nod/shake_head/tilt/smile/blink/expression/gesture/talk/pose），`at≤59s`、`duration 0.2–20`。
- 编译器四条硬校验：**拒写物理输出**（`PHYSICS_OUTPUTS` = physics3 的 Destination Id 集合）、
  越界夹紧 + warning、同参数轨道重叠 >0.015s 报错、motion3 四种段按 45Hz 重采样。
- LLM 只看到**语义能力目录**（33 个 PRIMARY、手势进出 motion 名），永远看不到 `Param36`；失败只修一次。
- 等价的东西我们已经有了（模型参数表 + motion 生成器 + 质量探针），缺的是「让 LLM 直接编排一段新动作」这层。

---

## 结论与方案

**不要整包替换**：没有一家有大脑，而我们的 AstrBot 链接、语义标记、触发门控、主动开口是这四家里唯一跑通过的。

推荐路线（按性价比排序）：

1. **换渲染底座**：以 fulaska 的 `src/stage/` 为底（engine / layers / pose-bus / regions / life / mouth / bubble），
   因为它对**这个模型**做了物理写点与参数仲裁，而我们现在的 easy-live2d 管线做不到。
2. **把我们的脑子装进去**：`astrbot.ts`（云端 SSE + `complete` 兜底 + 打字机）→ 语义标记 → `perform()`；
   `triggers`（勿扰/冷却/长按/连击/系统事件）→ 他们的 regions 手势事件；`proactive` 台词库直接复用。
3. **搬 petbox 的三件**：像素穿透、设置面板、mood 引擎 + 亲密度。
4. **借 jingyu 的一件**：动作 IR + 编译器校验，让她能"现编一段动作"，而不是只能在 13 个手势里挑。

分阶段：

- **P1** 把 fulaska 的 stage 拉进本仓（`stage/`），用我们的模型跑起来，验证渲染/物理写点/热区。
- **P2** 接 AstrBot：气泡 + 流式 + 语义标记 + 打断。
- **P3** 搬 petbox 面板/穿透/mood。
- **P4**（可选）动作 IR + 编译器。

`model.drawables.renderOrders`；而我们手上的官方 Core 是 **6.0.1**，这个属性已经改成方法
`model.getRenderOrders()`。结果：**任何模型都渲染不出来**（连官方样例 Hiyori 也一样），报

```
TypeError: Cannot read properties of undefined (reading '0')
  at doDrawModel (cubism.es.js:11456)   // const order = renderOrder[i]
```

一开始以为是"我们的 moc3 不兼容"，其实是版本对不上。`scripts/patch-core6.mjs` 给访问器加了三级兜底
（属性 → `getRenderOrders()` → 恒等顺序），打完立刻正常：

### 修掉的两件事：拖不动 + 只显示半个人

**① 左键拖不动。** 原版只有在**没有热区**的身体空隙上才允许左键搬窗口
（`app/renderer.js` 里 `dragWindow(stage, { canStart: (e) => !state.regionInput?.pressed?.region && bodyAt(...) })`），
而自动铺出来的热区几乎盖满整个角色 ⇒ 左键按在哪儿都算"互动"，只能靠中键搬窗口。

补了一条**直线拖判定**（`bindRegionDrag`）：按下后累计路径，
位移超过 `max(20px, 画布宽×5%)` 且 `路径长度 / 直线距离 ≤ 1.7`（够直）→ 认定为搬窗口；
来回划（比值过大）仍然走抚摸。增量用 `screenX/screenY`，**不用 `clientX`**：
窗口跟着鼠标走的时候 clientX 几乎不变，只有屏幕坐标才是真增量。

顺带记一条环境限制：这台机器上 `SetCursorPos` 返回 `false`（会话里没有注入输入的权限），
所以"真实光标"这条路验不了；验证改用页面内派发的 `PointerEvent`（显式给 `screenX/screenY`，
模拟真实鼠标的坐标变化）—— 10 次 ×14px 的拖动，扣掉起手阈值后位移 112px，和预期一致。

**② 窗口跑到屏幕外。** 保存的窗口高度 1131 大于可用区 867，重启后 `y = -264`：
头顶 264px 在屏幕外，看得见半个人。两处一起改：

- `app/main.mjs`：`fitWindowToWorkArea()` 等比缩到可用区内（宽高比不变），`clampToWorkArea()` 保证位置落在可用区；
- `app/renderer.js`：`fitSize()` 按 `screen.availWidth/availHeight × 0.94` 封顶，
  否则渲染层每次启动都会把 1131 的高度再下发回去，把主进程的修正覆盖掉。

### 拖动一闪一闪 / 在别的窗口里拖不动

**闪的根因：同一次拖动被搬了两遍。** `bindWindowDrag()` 里同时挂着旧路的 `dragWindow()`
和我们新加的 `bindRegionDrag()`，两个都在算 `screenX/screenY` 增量、都调 `shell.moveBy`：
一帧往左 120px、下一帧又往右 120px（`_data/app-run.log` 里 `[move] -100 120` / `[move] 100 -120`
交替出现），位移互相抵消，看起来就是窗口在抖。删掉 `dragWindow()` 这条旧路，只留 `bindRegionDrag()`
之后，日志里每次都是 `[move] 14 -3`，和鼠标增量一一对应。

顺带把搬窗口收敛到「一帧一次」：`pointermove` 里只累加，`requestAnimationFrame` 统一 flush
（外加 24ms 定时器兜底，防止窗口被遮挡时 rAF 被节流）；主进程改用 `win.setBounds()` 一次性到整数坐标。

**拖不动的根因：掩码过期 → 整窗穿透。** 透明处穿透是按「渲染出来的 alpha 掩码」判定的，
而窗口不在前台、被别的窗口挡住时渲染会停，掩码就停在**上一次鼠标位置**。鼠标明明已经移回她身上，
判定仍然是「透明」→ `setIgnoreMouseEvents(true)` → 点击穿到桌面去了，自然拖不动；
先用任务栏把桌宠窗口激活一下（重新渲染）就又好了 —— 这就是「必须切入桌宠才能拖」。

改法：`bodyAt()` 发现掩码超过 1.2s 没更新就不再信它，**按命中处理**（宁可多挡一下鼠标，
也不能让她点不到）；另外窗口重新获得焦点时强制刷新掩码并重算穿透，
拖动过程中失焦也不清 `pointerDown`（否则 pointerup 会丢，拖动卡死）。

### 为什么出现过两个桌宠（2026-11-10）

- 左边那个点不到的是**官方原生版 v1.1.2Beta 的 Demo.exe**：我为了验证「换引擎」这条路把它跑起来过。它启动日志里写着
  `[regions] no Parts in cdi3`、`[idle] routines missing`，热区数据缺失 ⇒ 整窗按透明处理 ⇒ 鼠标穿透到桌面，**点不到是预期行为**，不是坏了。
- 右边那个在用的是本仓的 Electron 版（`app/main.mjs`）。

### 拖拽最后一条闪烁来源（已修）

`bindRegionDrag` 原来用事件的 `screenX/screenY` 算增量搬窗口。但 Chromium 的 `screenX = 窗口原点 + clientX`，
窗口被自己搬动之后，下一帧事件的 `screenX` 已经把这次位移算进去了 —— 拿它再当增量就是**正反馈**：
一帧多走一段、下一帧又补偿回来，看起来一闪一闪，拖完位置还会偏。

改法：渲染层只负责**判定**「这是搬窗口」（直线拖）还是「抚摸」（来回划），判定成立就 `shell.dragBegin()`；
真正的位移交给主进程，它读 `screen.getCursorScreenPoint()`（系统光标是绝对量，不受窗口移动影响），
8ms 一次用 `setBounds` 连尺寸一起钉住，位移为 0 时不碰窗口。

### 「必须先点一下窗口才能拖」不是设计，是 bug（已修）

原来穿透判定在**页面里**做：渲染层读 alpha 掩码，判断指针在不在她身上，再叫主进程 `setIgnoreMouseEvents`。
问题是——窗口不在前台/被遮挡时，Chromium 会**停掉 rAF**，渲染停了，掩码也就停在「上一次鼠标位置」那一帧。
于是鼠标明明在她身上，页面却按旧掩码判成透明 ⇒ 整窗穿透 ⇒ 点击落到桌面。
点一下之后窗口获得焦点、渲染恢复、掩码刷新，就又能拖了。这就是「必须先点一下」的来历。

改法：**判定搬到主进程**。

| | 改前（页面判定） | 改后（主进程判定） |
|---|---|---|
| 谁看指针 | `pointermove` 事件 | `screen.getCursorScreenPoint()` 每 33ms 轮询 |
| 谁提供轮廓 | 页面内 `alphaMask` | 页面把掩码压成 1bit/格上传（`win:mask`，150ms 节流，500ms 强制刷新） |
| 页面被节流时 | 判定停摆 ⇒ 点不到 | 不受影响（主进程不依赖页面事件） |
| 掩码太旧 | 无兜底 | 超过 4s 一律当作「可点」 |

### 「一开始拖就闪一下」（已修，三个原因叠在一起）

1. `applyWindowSettings()` 每次穿透翻转都会调一遍 `setAlwaysOnTop` —— 这会让 Windows 重新排一次 z 序，正好赶上拖动第一帧，就是那一下白闪。现在**只在值变化时**才调。
2. 穿透判定在轮廓边缘会抖（掩码每 500ms 重拍一次，边缘格子会来回变）⇒ `setIgnoreMouseEvents` 反复翻转。现在改成施密特触发：
   - 还能点时 → 用**紧**半径（r=1 格）判定，真出了轮廓才放开鼠标；
   - 已经在穿透时 → 用**松**半径（r=3 格）判定，要离轮廓足够远才继续穿透。
3. 加上 400ms 迟滞：「可点 → 穿透」要等 400ms，「穿透 → 可点」立刻生效。

验证（不能注入真实光标，用页面内打到主进程的调试口 `shell.debugHit(x,y)`）：

```
219 410 {"hit":true}     ← 身体中央
 30  30 {"hit":false}    ← 左上角空白
219  60 {"hit":true}     ← 头顶
219 800 {"hit":false}    ← 脚下
400 400 {"hit":false}    ← 右侧空白
```

启动日志：`[mask] 首帧 110x205 rect 0 0 439 819`，之后**没有** `[hit] 忽略鼠标=…` 抖动 ⇒ 不再闪烁。

## P2 结果：接上云端 AstrBot（2026-11-10）

底座换成 fulaska 之后，第一件必须补的事就是「脑子」——三家参考项目都没有对话能力，
我们原来那套（云端 AstrBot SSE + `complete` 兜底 + 打字机 + 语义标记）直接搬了过来。

### 形态

```
舞台窗口（app/renderer.js）
  └─ 双击 → 聊天输入条 → Enter
        └─ shell.brainSay(text)  ──IPC──▶  主进程
                                            └─ app/brain/astrbot.mjs
                                                 POST http://124.220.193.183:6185/api/v1/chat
                                                 （Bearer key，stream，session_id = 记忆槽）
                                            ◀── SSE: plain×N + complete
                                            └─ 以 complete 为准，自己按 6–14ms/字 逐字回吐
        ◀── brain:ev (state/delta/done/error) ──
  └─ 气泡打字机 + [[act:…]] → motion / expression / pose
```

新增文件：`app/brain/{config,astrbot,mock,store,utils,index}.mjs`。
配置在工程根 `brain.config.json`（`astrbotUrl` / `astrbotKey` / `brain`），环境变量
`ASTRBOT_URL` / `ASTRBOT_API_KEY` / `PET_BRAIN=mock` 可覆盖。

### 为什么保留「以 complete 为准」

远端模型的 reasoning 会混在 `plain` 事件里一起推下来（实测样例：
`User says hi. Simple greeting, keep in character, short.` 后面才是正文）。
`complete` 事件里的 `data` 是**干净全文**，所以流里的 delta 只攒着不用，
最后按 6–14ms/字 自己打出来。代价是首字晚 0.5s 左右，换来绝不把内心戏打进气泡。

### 语义标记 → 动作

`[[act:nod,blush]]` / `[[face:expr_cry]]` / `[[wave]]` 三种写法都认；
渲染层按 `CHAT_ACTS` 表映射到三类原语：

| 原语 | 实现 | 例子 |
|---|---|---|
| `motion:<名字>` | 从模型 `model3.json` 的 `FileReferences.Motions` 建「文件名 → (group, index)」索引，`stage.motion(group, index, {priority:3})` | nod / shake / tilt / bow / yawn / surprise / hop / angry / pout / peek |
| `face:<expr>` | `layers.addExpression(name, params, {source:'agent', fade:0.2})`，2.6s 后整组撤掉 | blush / cry / tooth / loading / dizzy / sweat / heart |
| `pose:<预设>` | `poses.set(name, 320)` | 举手 / 竖手指 |

`priority: 3`（`MotionPriority.FORCE`）是必须的：默认优先级会被待机层吃掉。
表情用独立 `source: 'agent'` 层，不会被别的表情顶掉，也让「说完就撤」有唯一入口。

### 这一轮踩到的坑

1. **气泡会被待机台词抢走**：舞台自己的 idle/interaction 台词也走 `bubble.show()`。
   解决：发话时 `bubble.lock('chat')`，`done` 后 3.5s、`error` 后 6s、
   打断后 1.2s 再 `unlock('chat')`。
2. **长回复把她的脸整个盖住**：气泡没有滚动条、`pointer-events: none`。
   解决：气泡只显示**最后 150 字**（前面加 `…`），完整原文进 `stage-chat.jsonl`。
   对桌宠来说「刚说的最后一句」比整段原文更该被看见。
3. **Esc 打断不生效**：`dblclick` 处理器里写了 `e.target.closest(...)`，
   测试时事件派发到 window 上 `target` 没有 `closest` 直接抛错，后面的 `open()` 没执行。
   改成 `e.target?.closest?.(...)`。真实鼠标不会触发，但脚本化验证会。
4. **打断后字还在涨**：远端已经出队的 delta 不会因为你按 Esc 就停下。
   渲染层 `muted` 一旦置位就丢弃后续 delta/segment/done，直到下一次发送。
5. **CRLF**：`app/renderer.js` 是 CRLF，用 `\n` 拼的多行 `String.replace` 全部静默失败
   （`applyNow`、`setInterval`、`chatRender` 三处都中招过）。补丁脚本一律用
   单行锚点或 `\r?\n`。

### 验收（真机，非 mock）

  ⇒ AstrBot 侧上下文确实续上了（`sessionId` 落在 `_data/stage-home/stage-chat-state.json`）。
- 打断：9s 时按 Esc，气泡停在 274 字，2.5s 后仍是 274 字（`stopped: true`）。

## P2.2：气泡不收 / 输入框点不进去 / 表情一闪就没（2026-11-10）

三个现象，三个独立原因。

### 1. 必须点她一下，输入框才点得进去

不是气泡挡住了，是**窗口把输入框那一带判成了透明**：

- 穿透判定只看画布 alpha 掩码（`app/main.mjs` 的 `maskHit`），
  输入条是 DOM，不在掩码里；
- 鼠标停在她脚下那片透明区超过 400ms，主进程就 `setIgnoreMouseEvents(true)`，
  整窗点击穿透 —— 你点的是桌面；
- 点一下她的身体（不透明区）窗口才恢复可点，于是看起来像「要用气泡挤掉才能打字」。

修法：**把窗口里的 DOM 浮层也纳入命中判定**。

| 位置 | 改动 |
|---|---|
| `app/preload.cjs` | 新增 `setChrome(list)` → IPC `win:chrome` |
| `app/main.mjs` | `chromeRects` + `chromeHit(cx,cy)`；`updateHit` 里优先级：手动穿透 → 拖动 → **浮层** → 轮廓掩码 |
| `app/renderer.js` | `reportChrome()` 上报 `#chatbar/#tools/#recover/#toast` 的窗口内矩形；输入条开/关、窗口 resize、每 2s 各报一次 |

验收（`_probe/cdp-hit-grid.mjs` 打 ASCII 网格，`#`=命中、`C`=浮层、`.`=穿透）：

```
  40 ..#########...
 340 ....########..
 400 .....#####.##.
 760 CCCCCCCCCCCCCC      ← 输入条那一整行现在是「可点」
```

`window.shell.debugHit(输入条中心)` → `{"hit":false,"chrome":true,...}`，
原来这一带是 `hit:false, chrome:false`（等于穿透）。

### 2. 说完话气泡一直挂着

气泡 `done` 之后只是 `unlock`，没有任何超时，只有待机/互动台词来顶替它。

修法：`scheduleBubbleHide()` —— `done`/`error` 之后按字数算停留时间：
**6s 起步，每 30 字 +1s，上限 14s**；`thinking`/`delta` 一到就取消计时；
到点 `bubble.hide()` + `unlock('chat')`，输入条开着就把焦点还给 `#chat-input`。

验收（`_probe/cdp-verify-bubble.mjs`）：`+2s on:true` → `+8s on:true` → `+13s on:false`。

### 3. 表情一闪就没

根因在 `onBrainEvent`：`state:idle` 分支里无条件 `removeSource('agent')`，
而主进程在流结束后**紧接着**就发 `{t:'state',state:'idle'}` ⇒ 句末刚做的表情被一秒抹掉。

修法：

- `EXPR_HOLD_MS` 2600 → **7000**；
- 思考脸单独一个 source `chat-loading`（`flashExpression(name, ms, source)`），
  首个 delta 或 idle 时只收它，不再连累 `agent` 的表情；
- 摸/点出来的临时表情 `ttlMs` 6000 → **8000**（`createReactions({ ttlMs: 8000 })`）。

验收：同一句话在 +4s 的截图能看到腮红，+8s 已恢复（`_probe/face-cmp.png` 左右对比）。

## P3.1：她自己开口（台词由 AstrBot 现场生成）

不是本地台词库 —— 本地只负责「什么时候」，说什么交给云端那位鲸鸢。

实现分三层：

| 层 | 文件 | 职责 |
|---|---|---|
| 门控 | `app/proactive.mjs` | 纯逻辑：勿扰时段、刚聊完 90s、用户 90s 内有动作、今天超量、两次间隔、到点掷骰子 |
| 触发 | `app/main.mjs` `runProactive()` | 往对话里塞一段**旁白**（时间/星期/安静了几分钟/上次自己说过什么），走同一条 `brain.chat` |
| 呈现 | `app/renderer.js` `onBrainEvent` | `ev.source === 'proactive'` ⇒ 气泡换成淡青底（`data-state="proactive"`）、不弹「…」占位 |

1. **旁白不能被当成用户发言**。所以文案里明确写「此刻没有人跟你说话」，并要求「不要问有什么事/不要报我在/实在没话说就只回 `[[silent]]`」。

3. **频率先给「少」**：`few` = 启动后 3–8 分钟试第一次，之后 20–40 分钟一次，每天 ≤6 句，到点还要过一次 65% 骰子（避免准点报时感）。设置页可以改档，改完立刻重建定时器。

连着 `blush → squint → pout` 会三层同时挂着（眼半闭 + 腮红 + 撇嘴）。现在 `flashExpression()`
在 add 之前先 `removeSourceExcept(source, new Set([name]))` —— 同一来源只留一个表情。

## P3.2：在场感 —— 主人走开了 / 回来了

用 `powerMonitor.getSystemIdleTime()`（系统级空闲，键盘鼠标都算「在」），5 秒轮询一次，
按 **3 / 15 / 45 分钟** 切成三档。三档决定两件事：她说话的密度，和她演给自己的程度。

| 档位 | 触发 | 她会做什么 |
|---|---|---|
| `here` | 有人在动 | 正常：待机小动作 + 偶尔一句小台词 |
| `short`（3 分钟） | 刚走开 | 45 秒后嘀咕第一句（"人呢…"），之后 3 分钟一句，最多 2 句 |
| `long`（15 分钟） | 走远了 | 一声不吭地自己待着：待机动作降到 0.55 倍、**小台词全部闭嘴**（不对空屋子演）；第 2.5 分钟嘀咕一句 |
| `deep`（45 分钟） | 大概出门了 | 7 分钟后最多嘀咕 2 句，间隔拉开到 30 分钟 |

回来（`→ here`）时先让她 0.7 秒内抬头，再说一句很短的：旁白里明确要求
「不要说'欢迎回来'，不用问'你去哪了'，一句就够」——按离开时长她自己会选语气。

三条防烦人规则：

1. **一气只嘀咕有限次数**：`short` 2 句、`long` 3 句、`deep` 2 句，间隔递增，说完不再追。
2. **夜里静默**：落在勿扰时段（默认 23:30–07:30）时，走开和回来都不出声，她只睡觉。
3. **你一动就打断**：`proactive:touch` 挂在 pointerdown / 双击 / 发消息上，气泡由你接管。

落地的文件：

- `app/main.mjs`：`PRESENCE_STAGES`、`presenceStage()`、`AWAY_SCHEDULE`、`startPresence()`、`scheduleAway()`、`onReturn()`；

- `app/preload.cjs`：`onPresence(cb)`、`testPresence(kind)`（调试用，手动演一遍走开/回来）。
- `app/renderer.js`：`state.presence`；走开时 `idle.set({speed})` 降到 0.55 倍、`onLine` 直接 return（小台词闭嘴），
  回来恢复原速。
- 设置页「主动说话」新增开关：**我走开 / 回来时她会嘀咕两句**（`awayTalk`，默认开）。

### 还能往哪长（没做，先记着）

### 两个修正（2026-11-10）

1. **「等了 3 分钟没反应」的真因**：`scheduleAway()` 里有一道 `if (inNightHours()) return` ——

   现在取消这道夜间闸：她还醒着、屏幕还亮着，本来就该念叨两句（催睡是她的性格）；

   `走开（short）：第 1 句将在 20s 后`，以后不会再出现「静默失败」。
   首句延迟也从 45s 缩到 **20s**（3 分钟没动 + 20 秒 = 3 分 20 秒能听到）。
2. **气泡统一橙色系**（AstrBot 生成的话都算，本地舞台台词保持米白）：

## P3.3 她能自己换装（2026-11-10）

### 为什么要分「三层 ownership」

模型里有 23 个 exp3，其中一半不是表情而是**装扮**：`glasses` 黑框、`monocle` 单片、
`shoes_off` 光脚、`skirt` 长裙、`body1/body2` Q 版形态、`tail_off` 收尾、`tooth` 大牙、
`basin` 钢盆、`finger_on` 竖手指、`chest`。以前它们全走 `flashExpression()` 的
`source='agent'`，和「害羞」「生气」这些瞬时表情挤在同一层，于是：

- 做完表情 7 秒到点，`removeSource('agent')` 连眼镜一起摘了；
- 换两次装，上一层还挂着，出现「单片眼镜 + 黑框」同时戴。

所以拆成三层，谁写谁负责：

| 层 | source | 生命周期 | 谁在用 |
|---|---|---|---|
| 动作层 | `stage.motion()` | 动作时长 | nod / hop / 竖手指等 motion3 |
| 表情层 | `agent` | 7 秒（`EXPR_HOLD_MS`） | 害羞、生气、思考脸 |
| **装扮层** | `look` | **一直挂着，落盘** | 眼镜、裙长、鞋、尾巴、形态、大小 |

`applyLook()` 用的是 `layers.removeSourceExcept('look', 新的一身)`：同层互斥、跨层不打架。

### 槽位表（`app/look.mjs` 是唯一真相）

| 槽位 | 取值 | 对应 exp3 |
|---|---|---|
| `glasses` | none / glasses / monocle | — / `glasses` / `monocle` |
| `shoes` | on / off | — / `shoes_off` |
| `skirt` | short / long | — / `skirt` |
| `body` | 1 / 2 / 3 | — / `body1` / `body2` |
| `size` | small / normal / large | 不改模型，改 `settings.zoom`（0.55 / 1 / 1.2） |
| `tail` | on / off | — / `tail_off` |
| `tooth` | normal / big | — / `tooth` |
| `accessory` | none / basin / finger | — / `basin` / `finger_on` |
| `chest` | normal / boost | — / `chest` |

`normalizeLook()` 对非法槽位/取值**静默丢弃**——她会写错字，写错就当没说过，不要炸。

### 「大小」为什么单独一个槽位

`body1/body2` 不是等比缩小，是**换了一套 Q 版素材**（实测占画布只剩三成）。
一开始想按新轮廓反过来放大窗口让她填满，试了三条路都失败：

1. 按固定系数缩窗口（`BODY_SCALE`）→ 窗口小了，她还是那点大，等于更小；
2. 窗口 resize 后读 `alphaMask` 量实际轮廓 → GL drawing buffer 已失效，`readPixels` 全 0；
3. `renderer.extract.canvas()` 离屏量 ink 比例 → Q 版 0.257 vs 正常 0.262，量不出来。

结论：**「形态」和「大小」是两件事**。形态交给 exp3，大小交给 `settings.zoom`（现成的
`applyFit` 会跟着改窗口）。实测 `size=small` 窗口 437×816 → 334×623，`normal` 回 437×816。

后来还试过第四条：换形态之后再量一次 `alphaMask`（比例法，`measureBodyK()` 留在代码里）。
结果切到 Q 版后 `maskH` 直接变 **0** —— 换表情会触发一次全量重绘，那一帧的 drawing buffer
又是空的。所以最终**形态不动窗口**：Q 版那套素材自带留白，量不出可信倍率，
真正让「窗口跟着人走」的是 `size` 槽位。

## P3.4 装扮面板 + Q 版「裁切放大」（2026-11-10）

### Q 版为什么"缩了也还是小的"
引擎永远把**整张 model 画布**映射到窗口。所以窗口缩到 181×306 时，她也同比缩 —— 白缩。
真正能让她"在屏幕上一模一样大、但占的地方更小"的只有**裁切**。

做法（不加引擎 API）：拿到她在画布里的包围盒 `inkBox()`（`extract` 离屏扫 alpha，不依赖
`readPixels`），然后给 `#stage canvas` 上 CSS 变换：

```
transform: scale(k) translate(-box.x, -box.y);  transform-origin: 0 0
k = min(W / box.w, (H - 6) / box.h)   // 上限 3.4，小于 1.3 就不做
```

等价于把画布裁到她身上再放大铺满窗口。实测 Q 版 `k≈3.1`，她填满窗口（截图 `_probe/chibi-crop.png`）。
正常形态 `body==='1'` 时 `resetViewCrop()` 把 transform 清空，避免多一层重采样糊掉。

### 命中判定要跟着反变换
掩码是**画布坐标**，鼠标是**窗口坐标**，中间隔了 `view = {k, bx, by}`。
- 有 `view` 时不要拿掩码逐像素算（`getBoundingClientRect` 自己也带变换，会双重变换）——
  直接用 `hitBox`（她变换后的包围盒 ±8px）判定，够准且绝不会点不到；
- 没有 `view` 时照旧走掩码 + 3×3 膨胀。

`inkBoxWin()` 负责把画布包围盒换算成窗口坐标（`x' = (x - bx) * k`），`reportHitBox()` 与
`scheduleChromePos()` 都改用它，否则 `hitBox` 里存的是裁切前的小盒子，中心点会被判成"外面"。

### 输入条贴脚
`positionChatbar()`：`#chatbar` 改成 `top = box.y + box.h + 10`（`bottom: auto`），
换装 / 开输入条 / 启动 / 窗口 resize 后都重排一次（`scheduleChromePos`）。
这样 Q 版、小只、大只都不用再靠缩窗口来"让输入条跟上"。

## P3.5 Ctrl + 滚轮：平滑缩放（2026-11-10）

### 手感怎么来的
不是"每滚一格跳一档"，而是**指数趋近**：滚轮只改目标值，渲染循环每帧朝目标靠一段，

```
v += (target - v) * (1 - exp(-dt / τ)),  τ = 0.11s
```

`1-exp(-dt/τ)` 让起步走得快、越接近越慢 —— 这就是"加速减速"。单帧位移与剩余距离成正比，
所以快速连滚会自然叠加成一条连续曲线，不会卡在档位上。

### 最终形态：窗口常驻最大，缩放只发生在画布
前两版都在跟"窗口尺寸"较劲（先不重排、收尾补一次；或者滚轮先改窗口再补偿），
结果分别是"放大被窗口切+停下闪"和"一卡一卡+她还会漂"。根因是同一个：
**透明窗口上 setBounds 会重开 WebGL 画布**，任何"跟着缩放改窗口"的方案都躲不开那一两帧空白。

所以改成：**窗口尺寸与缩放彻底解耦**。

```
窗口 = fitSize(zoomCap())     // 永远按最大档开窗，之后不再变
视觉 = scale(zoom / cap)      // 滚轮只改画布内容倍率
```

- 全程 **0 次 setBounds** ⇒ 没有空帧，也就没有闪；没有重排，也就不会"移动位置"；
- 她变小之后，窗口里是她周围的透明区域，不会挡住桌面（命中框仍是 `inkBox` 量出的真实包围盒）；
- 输入条按缩放后的包围盒定位，仍贴着她的脚；
- `settings.zoom` 的语义从"窗口倍率"变成"内容倍率"，最大值 = `cap`。

代价：窗口面积固定为最大档，显存/合成都按这个尺寸算（本机 437×816，可忽略）。

### 两个后续修复（常驻最大窗之后）
- **"最后闪大一下"**：`resetViewCrop()`（换形态/换装后的裁切复位）原来直接把 `canvas.style.transform = ''`，
  等于把缩放那一层也一起抹掉 → 收尾那一下她会瞬间回到满尺寸。现在只清 `state.view`，再 `composeCanvasTransform()` 重新合成。
- **输入条越缩越往上跑**：`inkBox()` 用 `canvas.getBoundingClientRect()` 取尺寸，而画布上挂着 CSS 缩放，
  rect 是**变换后**的尺寸，再乘一次 zoom 就是双倍缩放。改成用 `clientWidth/clientHeight`（布局尺寸）后，
  输入条会稳定贴在她脚下；收尾还会立刻重量一次，不等 700ms。

### 屏上放得下才是真的能放大
`zoomCap()` 按屏幕可用区反算上限：

```
cap = min(ZOOM_MAX, availW*0.94 / w(zoom=1), availH*0.94 / h(zoom=1))
```

这台机器她默认已经顶到高度上限（可用区 867），所以 `cap ≈ 0.72`——再往上滚不会有任何反应，
这是**预期**，不是失灵。缩小的方向是自由的（实测 437×816 → 282×526）。

### 踩坑：放大/缩小之后"点不到她了"
`alphaMask` 在窗口 resize 后会整张错位（GL buffer 失效），而主进程原来**优先**用掩码判定，
于是鼠标在她身上也被判成"透明"。现在判定顺序反过来了：

1. 有 `hitBox`（渲染层 `extract` 量出的窗口坐标包围盒）→ 用它 ±6px 判；
2. 只有在没有 `hitBox` 时才退回像素掩码。

另外缩放松手后会强制重画两次掩码（280ms / 900ms）并清零节流，避免旧网格继续生效。
实测：缩放前后 `hit(中心)=true`、`hit(角落)=false`。

## P5：让她出声（TTS 流式播放 + 口型）

链路：AstrBot 文本增量 → 渲染层按句切分 → 主进程代理 `POST :8769/tts_stream` → 裸 PCM(48k/16bit/mono)
→ 渲染层 AudioWorklet 队列 → WebAudio 出声 + RMS 驱动 `ParamMouthOpenY`。

四条必须记住的实现要点：

1. **不要「一块一个 BufferSource」**。网络到达时刻不确定，早到会叠在同一时间点（相加削波）、
   晚到会留缝（咔）。AudioWorklet 由音频线程自己拉队列，天然不重叠不留缝。
2. **裸 PCM 按字节切块会错位**。`reader.read()` 给的长度可能是奇数（实测 13315），
   按 int16 解就会整体错半个采样 —— 听感是强烈的滋滋声。主进程攒字节、只发偶数长度。
3. **24k→48k 不能用 `np.repeat`**。最近邻把波形变成台阶，12–24kHz 镜像全叠上来，同样是滋滋声。
   用 soxr 流式重采样（带抗镜像滤波）。同类项目之所以没事，是因为它们的语音通道里
   `_Decimator48to24` 会低通+抽取，正好滤掉镜像。
4. **电平要钳位**。`(rms - 0.008) / 0.10` 再 clamp 0–1；停掉 300ms 后强制归零，
   否则口型会停在半张。

诊断口：`window.__voice()` 返回 `{chunks, queued, level, peak, jumps, samples, sec}` ——
`jumps` 是「相邻采样跳变 >0.6」的计数，干净语音应当是 **0**，一有噪声它立刻上千。


## P5 结果：让她出声（语音 + 口型 + 句级同步）

### 声音从哪来

- 本地 TTS 服务 `app/tts/server.py` 跑在 **:8769**，模型 **Qwen3-TTS 0.6B**（`D:oice-lab\qwen3tts-0.6B`），克隆参考音 `ref_m3.wav`（71 字原文当 ref_text）。
- 四份「情绪母带」在 `app/tts/voices/`：`soft / angry / sleepy / happy`，都是同一把声音、只换 `instruct` 与 `temperature` 生成，再作为参考音复用 —— 这样情绪切换不会换人。
- 接口：`GET /health`、`POST /tts_stream {text, voice}` → `audio/L16` 48k 流、`POST /voice/default`。

### 三个坑（都实测定位）

1. **滋滋声 ①**：服务端 24k→48k 用 `np.repeat(y, 2)` 最近邻上采样，台阶 + 12–24k 镜像 = 持续嘶声。改成 `soxr.ResampleStream` 流式重采样。
2. **滋滋声 ②**：主进程把每次 `reader.read()` 的裸字节直接 base64 下发，而 chunk 长度会出现 **13315（奇数）**，渲染层按 int16 解就整体错半个采样。改成攒字节只发偶数长度：`const even = buf.length & ~1`，余数留到下一轮。
3. **嘴不动**：`src/stage/mouth.js` 的 `apply()` 里 `else if (levelTarget > 0) levelTarget = 0` 会把外部 `speak()` 喂进来的电平**每帧清零**，只有 `talk(ms)` 那条假说话包络能活。加 `levelUntil = now + 300` 保鲜，清零条件改成 `performance.now() > levelUntil`。

### 链路

```
AstrBot delta ─→ pumpSentences() 切句（首句允许逗号切）
                     │
                     ├─ shell.ttsSpeak({text, voice, token}) ─→ 主进程 fetch :8769/tts_stream
                     │                                          └─ base64 chunk ─→ 渲染层
                     └─ startItem(i)：把这一句文字推上气泡（chatState.revealed += text）
                                              │
                     AudioWorklet(StreamPlayer) ┘ 带通 120–1200Hz → 包络 → level
                                              │
                        onBeforeUpdate：mouth.speak(level*0.75) → 口型 + 音节抖动
```

- 气泡文字**按句出现**（不是打完再整段），全部念完后再多留 1.2s 才收。
- 语音关掉时走旧路径：文字照流式长出来，按字数 6–14s 收起。

### 开关

- 右键装扮面板底部 `声音 / 静音`，或全局 `Ctrl+Alt+M`（关掉会立刻 `abortTts()`）。
- 存在 `settings.voice`，重启保持；本项目没有托盘，所以没有第三处入口。

### 验收数字

| 项 | 结果 |
|---|---|
| 音频块 | chunks 5–10、**全偶数长度**、跳变 0 |
| 首句上屏 | ~3.2s（首句在逗号处切开；旧路径首字 5.3s） |
| 气泡收起 | 语音 10.2s 结束 → 11.1s 收起（+0.9s） |
| 口型 | 电平 0.15–0.26 → `ParamMouthOpenY` 0.10–0.35，随机音节换口型 |
| 语音关 | 首块不再产生（chunks 冻结）、文字一次性长全、6–14s 收起 |

## P5.2 工作联动：她在陪我干活（2026-11-12）

数据源不写插件也能拿到：DSH 的 dsh-pet 插件把工作状态挂在 **`GET /dsh-pet-7340/state`**：

```json
{"sections":{"workStatus":{"counter":1794412906529,
  "data":{"state":"working","task":null}}}}
```

`state` 六档（`thinking / working / result / waiting / success / error`），`counter` 每次变化才算一次新事件。

**实现**：

| 位置 | 干什么 |
|---|---|
| `app/worklink.mjs`（新） | 700ms 轮询；端口靠 `netstat` 扫 `127.0.0.1` 的 LISTENING 端口、逐个探 `/dsh-pet-7340/state`；DSH 没开退到 5s 重试；`counter` 去重 |
| `app/main.mjs` | 起 `workLink`，把状态转成舞台已有的 `agent:status` 通道；设置项 `workLink: off/motion/full`；IPC `worklink:status` / `worklink:refresh` |
| `src/stage/agent-link.js` | 补了 `EXPR_ALIAS`（`屑屑眼→expr_sneer`、`加载→expr_loading`、`＞＜→expr_squint`、`兔牙→expr_tooth`、`流冷汗→expr_sweat`、`黑框眼镜→expr_glasses`），否则中文表情名永远找不到；`silent` 支持「只动不说」 |
| `src/stage/phrases.js` | 补 `result` 档台词（原来只有 thinking/working/waiting/success/error） |
| `app/settings.html` + `settings.js` | 「工作联动」三档下拉 |

**复用了舞台自带的 agent 联动**，没有重写：表情、`poses.set('竖手指')`、气泡锁、终态几秒后自动收起，都是原来 `src/stage/agent-link.js` 的逻辑，我只负责喂状态。

**验收**（注入六档截图）：`thinking` → 「这个…有点绕。」+ 屑屑眼；`waiting` → 「要你点个头才行呀。」+ ＞＜；`success` → 「你看，完成啦。」+ 兔牙 + 竖手指；`result` → 「好，下一个。」；`motion` 档确认不弹台词。真机也在跑：日志里能看到 `[work] state=working mode=full` 随我调工具变化。
