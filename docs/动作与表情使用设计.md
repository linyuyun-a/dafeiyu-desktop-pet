# 动作与表情使用设计（怎么用，不是怎么做得出来）

> 日期：2026-11-06　状态：方案，未施工
> 输入：21 个动作 + 23 个表情 + 9 个配件 + 3 档体型（右键菜单已全部可达）
> 参考：VTube Studio 参数优先级模型、Shimeji-ee 行为表、SillyTavern 表情分类映射

---

## 0. 一句话结论

**桌宠好看的关键不是"动作多"，而是"绝大多数时间不动，动的那一下刚好对"。**
所以本设计的核心是**调度**（什么时候允许动、动哪个、动多久、和谁搭配），不是再加动作。
现有 21 个动作已经够用；缺的是①情绪→表情+动作的映射表 ②节律层（多久犯一次小动作）③忙碌/抢占规则。

## 1. 从三个成熟案例里各拿一样东西

| 来源 | 拿什么 | 用到哪 |
|---|---|---|
| VTube Studio | 参数打架时的**优先级链**：默认 < 待机动画 < 面捕 < 一次性动画 < 表情 < 物理；一次性播完平滑淡回下一级 | 我们反过来用：**我们的"面捕"= 视线跟随**，它必须能被一次性动画临时压制，播完再接管 |
| Shimeji-ee | **行为表 + 权重转移**：`behaviors.xml` 里每个行为给 Frequency，按比例当概率（不用凑 100），动作播完才转移 | 节律层调度器：一张"闲置时可能做什么"的权重表 |
| SillyTavern | **情绪→(表情, 动作) 映射配置**：28 个 GoEmotions 标签归并到少数几个表情/动作，LLM 只输出一个词 | 对话联动层：AstrBot 回包 → 情绪标签 → 查表出表情+动作 |

三个都指向同一件事：**动作不是随机放的，是"状态 → 查表 → 执行"**。

## 2. 四层调度（我们的实际分层）

```
L3 事件层   系统/对话事件：早安、深夜、报错、说完话        ← 低频、优先
L2 节律层   闲置时按权重犯小动作：歪头、看四周、打哈欠      ← 30s 起，越久越频繁
L1 反射层   用户直接摸：点、拖、悬停                       ← 立即，最高优先
L0 常驻层   Idle 循环 + 物理 + 呼吸 + 视线跟随              ← 永远在，但可被压制
```

**参数纪律（实测得来，违反就出 bug）**

| 想干的事 | 正确写法 | 错误写法（会被物理覆盖） |
|---|---|---|
| 摆姿态（转头/鞠躬/歪头） | `setParameterValueById('ParamAngleX', …)`（覆盖表，在物理之后） | 写 `AngleX`（物理看不见） |
| 做动作 | motion3 里写 `AngleX` / `PositionX` 等 **OP 输入** | motion3 里写 `ParamAngleX`（物理归零） |
| 换装/形态 | 写 `Clothes1..5` / `key9..12` / `LeanInput`（自由参数） | 靠 exp3 再叠一层 |
| 物理输出参数（`ParamAngle*`、`FrontHair*`、`Skirt*`、`Param_Angle_Rotation84..89`…） | **只读，永远不当动作目标** | 手动硬写会撕裂/穿模 |

## 3. 21 个动作：谁在什么时候用

### 3.1 常驻类（不手动触发）

| 动作 | 时长 | 用法 |
|---|---|---|
| `idle` | 5.98s 循环 | 常驻。只在启动和动作结束后接管；**不要**手动频繁重播（会打断物理余摆） |

### 3.2 成对开关类（必须"进 → 出"两段连着播）

| 动作对 | 时长 | 场景 | 冷却 |
|---|---|---|---|
| `hand_up` → `hand_down` | 1.13 + 1.02 | 被摸头/被点名时"抬手"打招呼 | 8s |
| `grass_out` → `grass_in` | 1.23 + 1.13 | 娱乐彩蛋：拿狗尾草逗你 | 90s |
| `point_out` → `point_in` | 1.25 + 1.25 | 说话时"你听我说"竖食指 | 20s |

> 现有 `behaviour.ts` 已处理：`TapBody` 组不许单播（单播手停在半空），走 `playHandSequence`。
> `Prop`/`Emote` 目前是**单播**——这是遗留问题，下一步也应改成成对序列。

### 3.3 一次性手势（13 个，主力表达）

| 动作 | 时长 | 什么时候用 | 默认配对表情 |
|---|---|---|---|
| `nod` | 0.9 | 听懂/同意/应答（对话回包后） | 无（保持现状） |
| `shake` | 1.05 | 拒绝/否认/被逗 | `dizzy` 或 `sneer` |
| `tilt` | 0.85 | 疑惑/好奇/被盯着看 | `squint` |
| `bow` | 1.6 | 道歉、道谢、被夸奖 | `blush` |
| `look_around` | 2.2 | 走神、等待、刚被唤醒 | `squint` |
| `yawn` | 2.5 | 深夜 / 长闲置 | `squint` |
| `surprise` | 0.95 | 突然被点、桌面事件 | `tooth` |
| `angry` | 1.45 | 被连续戳、被拖来拖去 | `sneer` |
| `sleepy` | 2.6 | 210s 无互动 | `squint`（配 60s 长表情） |
| `hop` | 0.8 | 开心、早安、被摸 | `blush` |
| `pat_shy` | 1.6 | 摸头（最高频） | `blush` |
| `peek` | 1.3 | 偷看、从屏幕边缘探头（拖动后） | `blush` |
| `pout` | 1.7 | 撒娇式生气（比 angry 轻） | `sneer` |

### 3.4 大表演（独占）

| 动作 | 时长 | 用法 |
|---|---|---|
| `escape` | 13.15s | **彩蛋**：连点 10 次 / 长按 3s 才触发；全程 `busy`，期间屏蔽节律层与视线；冷却 10 分钟 |

**结论**：真正"日常"的动作只有 13 个手势 + 3 对开关；`escape` 是彩蛋。**不要再加动作，先把这 13 个用对**。

## 4. 23 个表情：分成三类，走三条不同的路

| 类 | 表情 | 走哪条路 |
|---|---|---|
| 情绪（9） | `heart` `blush` `cry` `sweat` `dizzy` `sneer` `squint` `tooth` `blackface` | 情绪流：临时表情，到点回 `default` |
| 道具/配件（11） | `glasses` `monocle` `basin` `lean` `chest` `shoes_off` `skirt` `tail_off` `finger_on` `finger_off` `body1` `body2` | **不进情绪流**，只走右键菜单/换装状态机（持久，不自动恢复） |
| 基础（3） | `default` `loading` | `default` 是归宿；`loading` 给"思考中/加载"用 |

### 4.1 情绪→表情+动作 映射表（照抄 SillyTavern 的 classify_mapping 结构）

| GoEmotions 标签 | 表情 | 动作 | 停留 |
|---|---|---|---|
| joy / amusement / excitement | `tooth` | `hop` | 1.5s |
| love / caring / admiration | `heart` | `pat_shy` | 2.0s |
| gratitude / approval / relief | `blush` | `bow` | 2.2s |
| sadness / grief / disappointment | `cry` | `sleepy` | 3.0s |
| anger / annoyance / disapproval | `sneer` | `angry` | 2.0s |
| surprise / realization | `tooth` | `surprise` | 1.2s |
| confusion / curiosity | `dizzy` | `shake` | 1.8s |
| nervousness / fear / embarrassment | `sweat` | `look_around` | 2.0s |
| neutral | `default` | `nod` | 0.9s |
| （兜底） | `default` | 无动作 | — |

> 28 个标签里两三个归到同一格是**故意的**：我们有 9 个情绪表情，28 个标签，必须归一。
> 情绪只在**回包结束**时判一次（不是每个 token 都判），一次对话一个情绪。

### 4.2 表情停留时长

| 类型 | 时长 | 例 |
|---|---|---|
| 微表情 | 900–1200ms | `tooth`（惊讶） |
| 常规 | 1500–2500ms | `blush` `sneer` |
| 情境 | 至 60s | `squint`（困），`loading`（思考中） |

## 5. 节律层：怎么"看起来活着"还不烦人

借鉴 Shimeji 的权重表（Frequency 当相对概率，不要求和为 100）：

| 闲置时长 | 候选行为（权重） |
|---|---|
| 30–75s | `tilt`(3) `look_around`(2) `peek`(1) |
| 75s+（fidget） | `hop`(2) `pout`(1) `look_around`(2) `nod`(1) |
| 210s+ | `sleepy`(5) + `squint` 长表情 |
| 深夜 23–3 点 | 权重表整体换成 `yawn`/`sleepy` 为主 |
| 早晨 6–10 点 | 只触发一次 `hop` + `blush`（6 小时冷却） |

**铁律**：动作之间留 `1.5×时长` 的空窗；`busy` 期间绝不插队（只允许换表情）。
现有的常量为 `IDLE_FIDGET_MS=75000`、`IDLE_SLEEPY_MS=210000`，节律层直接接入即可。

## 6. 反射层：用户动手

| 输入 | 现在的行为 | 建议 |
|---|---|---|
| 点头部 | `blush` + `pat_shy` | 保持；连点 3 次 → `heart` + `pout` |
| 点身体 | `blush` + 随机 TapBody | 改成 `tilt`/`shake` 循环，避免死循环抬手 |
| 快速连点 | `sweat` + 随机 | 保持；5 次以上 → `angry` + `angry` |
| 拖拽开始 | 闭眼 + 惊 | 保持 |
| 松手 | `dizzy` + `shake` | 保持；松手速度 > 阈值 → `peek` |
| 悬停 1.3s | `look_around` | 改成 `nod`（更低调） |
| 双击 | 打开聊天 | 保持 |

**优先级**：反射层 > 节律层 > 事件层。反射层永远能打断节律层；事件层只能排队。

### 6.1 分区反应表（已实现，`zones.ts` + `triggers.ts`）

引擎只有 `Head`/`Body` 两个 HitArea，按 drawable 包围盒算还落在头发外侧，所以命中改由"内容框归一化分区"判定，共 11 区：

| 分区 | 反应 | 用到的参数/动作 |
|---|---|---|
| Head（头顶/发顶） | 害羞：闭眼低头 + 抬手 | `pat_shy` / `hand`（TapBody 成对） |
| Face（脸/眼/嘴） | 脸红 + 嘟嘴 | `blush` 1400ms + `pout` |
| EarL / EarR（兽耳鳍） | 耳鳍立一下 + 歪头 | 脉冲 `LEar1..3` / `REar1..3` → 1（320ms）+ `tooth` + `tilt` |
| Chest（胸口/围裙） | 护胸 + 脸红 | 脉冲 `Movement2`（抚胸）900ms + `blush` 1700ms |
| Skirt（裙摆） | 护裙：裙摆被带起来 + 屑屑眼 | 脉冲 `SkirtX1..4` → 0.45（520ms）+ `sneer` + `pout` |
| Legs（大腿） | 并腿 + 尴尬 | 脉冲 `Param33` → −1（600ms）+ `sweat` + `shake` |
| Feet（脚） | 跳一下 + 大牙 | `hop` + `tooth` + 冲量 1.2 |
| Tail（尾巴：鳍 + 两侧环） | 整圈弹一下 + 惊 | 脉冲 `Param_Angle_Rotation84..89` → 12°（520ms）+ `surprise` + `tooth` |
| HandL / HandR（手） | 抬手 / 竖食指 | 成对 `TapBody` / 成对 `Emote` |

实现要点（踩过的坑）：

1. **参数脉冲走覆盖表**（`secondary.pulse`），在物理之后应用，所以能看见；写 `LControl`/`RControl` 这种"物理输入"是无效的——物理读的是本帧开场快照，覆盖值进不去。耳鳍必须直接写 `LEar1..3`/`REar1..3`（物理输出参数）。
2. **分区键也算"用户亲手点"**：`gate()` 原先只认 `Head:`/`Body:` 前缀，新分区键在忙碌时会被拦掉，表现为"点了没反应、只演通用规则"。改成按后缀 `/:(tap|rapid|hold)$/` 判。
3. **耳朵/手/尾鳍的判定必须排在躯干之前**，否则手和尾巴环永远被 `Chest`/`Legs` 吃掉；尾部环在腿两侧，所以 `Tail` 排在 `Legs` 前。
4. 每个分区都有 `FALLBACK_ZONE`（Face/Ear→Head，其余→Body），只写了 `tap` 规则时，长按/连点/悬停自动退回通用规则。

### 6.2 成对动作（已实现）

`Prop`（狗尾草出/回）、`Emote`（竖食指出/回）、`TapBody`（举手/放下）在原素材里都是**两段开关动画**，单播任一段会让手停在半空、道具挂在身上不收回。按 VTS"一次性动画必须能淡回"的规则，统一走 `{type:'pair'}`：组内 #0 播完（`holdMs`，默认取 #0 时长 −150ms、最少 600ms）自动接 #1，期间 `markBusy` + `gaze.suspendHead`。右键菜单里点这两组的任意一项，也从 #0 开始成对播。

## 7. 对话联动（AstrBot 接上之后）

| 阶段 | 表现 |
|---|---|
| 发送中（等回包） | `loading` 表情（8s 上限）+ 低速 `look_around` |
| 流式输出中 | 口型（`ParamMouthOpenY` 手动驱动）+ 每 2 句插一个 `nod`；**不换表情** |
| 出气泡 | 气泡出现时 `sweat`/`blush` 按内容挑一个 |
| 回包结束 | 判情绪 → 查 §4.1 表 → 表情 + 动作（这是"聊天气质"的来源） |
| 报错 | `sweat` + `shake` |

> 产业调研里"生命感幻灭"的根因是记忆不一致，不是动作少。动作层的价值是**让文字有身体**，不是抢戏。

## 9. 抢占与互斥（实现时的判断顺序）

```
1. 勿扰 / 用户正在打字（勿扰模式）  → 只允许 L0 + 反射层的表情，不播动作
2. busy（动作未播完）              → 只允许换表情，不插动作
3. 冷却未到                        → 放弃
4. 同组成对动作（hand/prop/point） → 必须成对，不能单播
5. 通过 → 执行，markBusy(时长 + 250ms)，gaze.suspendHead
```

现有 `triggers.ts` 的门控顺序已经覆盖 1–3；4 已补（`Prop`/`Emote`/`TapBody` 全部成对播，见 §6.2）。

### 12.2 三种"畸形"的来源（都是实测，不是猜）

1. **关键帧参数写到中间值**：`Clothes2`(大小变) 的 keys 是 `[0, 0.4, 1]`，对应三套画好的网格。写到 `0.5` 时网格被线性插值拉开，整个人是"头巨大、身体塌缩"（`_probe/grid-distort.png` 第 5 格）。
   ⚠ 表情 `体型1/体型2` 有 1s 淡入，**淡入过程必然经过中间值** ⇒ 切形态不能靠表情，要靠 wardrobe 一次性写值。
2. **半身开关与手臂脱节**：手臂放下后 `Movement1/3` 还 >0，手部贴片/狗尾草会留在半空（同上图第 6、7 格）。
3. **手臂链给到 1 却不同步**：只推 `Param62` 不推 `Param59/60/61`，袖子会脱肩。

### 12.3 `src/renderer/src/safety.ts`（已接线，10Hz）

|---|---|---|
| 形态吸附 | `Clothes2` 不在 `{0,0.4,1}` 且偏差 >0.01 | 吸附到最近档 |
| 越界夹回 | `Clothes1..5` / `Movement1..3` / `Param38` / `Param40` / `LeanInput` / `CheeckPuff` 超出 min/max | 夹回并写回 |
| 半身开关守卫 | `Movement1/3`>0.05 且 `max(Param36,Param39)`<0.25 | 强制置 0 |
| 半身开关守卫 | `Movement2`>0.05 且 `max(Param62,Param59)`<0.25 | 强制置 0 |

日志 `[safety] …`（3s 去重），`repairs` 计数可用于验收。
**注意**：只有 `Clothes2` 做关键帧吸附。`LHand`/`Movement2` 这类参数也有 keys，但物理会把它们写成 0.02~0.04 的小数，吸附会掐死自然抖动（第一版踩过）。

### 12.4 勾手指 `finger_tap`（第 14 个手势，1.6s）

抬右臂到斜上（`Param36` 0→**0.72** / `Param39` 0→**0.62** / `Param41`→**0.07** / `Param42`→**0.06**）→ 食指+手腕连勾两下（`Param43` 0→0.9→-0.27→0.8→-0.2→0、`RHand2`、`RWrist` 同步）→ 1.24s 后整条手臂回 0 → 末尾眨眼。

**别弯小臂**：第一版把 `Param41`/`Param42` 推到 0.8/0.55 想做出"手抬到胸前"的效果，实拍是**小臂向后倒折**（`_probe/grid-armfold.png`：0.55 以上开始折，1.0 直接把袖子拧到背后）。这个模型的肘关节只有一个旋转方向，往正方向加值就是反折。
安全写法：**手臂要么接近伸直（`Param41/42` ≤0.15）抬起来，要么完全放下**；需要"手在胸前"就用 §12.5 的抚胸组合（左臂 0.55/0.35/0.75/0.35），不要靠小臂折。

实拍校验帧：`_probe/grid-fingertap5.png`（620/860/1080/1350ms），手臂伸直、手指在勾、收回干净。

### 12.5 抚胸（`Chest:tap`）的正确姿势

不能只给 `Movement2`（胸口会多一块贴片），也不能把手臂全推到 1（袖子脱肩）。实拍选定的组合（`_probe/grid-chest.png`）：

```
Param62 0.55 / Param59 0.35 / Param60 0.75 / Param61 0.35，Movement2 1
手臂 1040ms 收回、Movement2 860ms 先收回（手先落会插着贴片）
```

## 13. 对话框入口（避开连点）

原来"双击任意位置 = 打开对话框"，但双击本身就会命中连点规则（1300ms 内两次 = `Head:rapid` / `Body:rapid`），一次双击会**先冒一个表情再弹对话框**，等于演两遍。现在改成三条入口，都不和连点冲突：

| 入口 | 行为 |
|---|---|
| **Ctrl + 单击** | 任意位置打开/关闭对话框（不触发抚摸） |
| **右键菜单第一项**「跟她说话…」 | 同上（原生菜单，也能给触屏/遥控用） |
| **双击空白处**（没落在任何分区） | 同上；双击落在模型上则什么都不做，交给连点规则 |

实现：`main.ts` 的 `endDrag` 里短按分支先判 `e.ctrlKey`；`dblclick` 先 `hitZoneAt()`，有命中就 return；`action-menu.ts` 顶层加 `{ id: 'chat' }` 叶子节点 + `onChat` 回调。菜单可达条目从 66 变 68。
