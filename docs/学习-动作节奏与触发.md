# 动作为什么会"不自然"，以及触发怎么设计

> 这一轮做了两件事：把 13 个手写动作重做成"有预备、有回弹、有错峰"的曲线，并把"什么时候演什么"
> 从 main.ts 里的几个 if 换成一条可查表的触发管线。下面是对应的学习笔记和落地记录。

## 一、官方给的是七条"反机器人"规则

来源：[Live2D 官方 · 提高动态质量的技巧](https://docs.live2d.com/zh-CHS/cubism-editor-tutorials/motion-hint/)

| # | 规则 | 不照做的症状 | 我们怎么落地 |
|---|---|---|---|
| 1 | 只转脸不带动身体 → 机器人 | 头像单独漂移 | 每个转头动作同时给 `PositionX/PositionY` 一点位移 |
| 2 | 脸和身体**同一时刻**动仍像机器人 | 整块画在平移 | 身体比头晚 2–4 帧（33–200 ms 错峰） |
| 3 | 后坐力 / 踩刹车 | 动作像被硬切 | 预备 → 冲过头 → 回弹 → 收尾，不是直线到目标 |
| 4 | 人的习惯动作 | 眼神乱转不眨眼 | 转头/换视线处插眨眼，说话给"开始说话"的脸 |
| 5 | 微妙眉毛 | 表情只有嘴在动 | 13 个动作里 9 个带 `ParamBrow*` |
| 6 | 张弛 | 大小动作一样重 | 小动作 |峰| ≤ 6，大动作 ≥ 18 |
| 7 | 符合角色 | 谁演都一个样 | 她是「年轻女性」：整个身体动 + 歪头，不沉稳 |

## 二、这台模型上，"不自然"的四个真实原因

1. **幅度底噪太低。** 实测把这套 rig 的 `AngleX/AngleY/AngleZ` 给满 ±30，头部在画面上也只有几度变化
   （`_probe/head-zoom.png`）。所以自然度不靠"摆更大"，靠**时机**。
2. **没有预备和回弹。** 旧版全是线性密点，起手即到、到点即停 → 观感就是"画在平移"。
3. **没有错峰。** 头、身、眼、眉同帧动，正好踩中规则 2。
4. **触发太单一。** 只有"戳头/戳身体"两种输入，同一个动作反复播，人一眼就看穿。

## 三、重做的动作生成器（`scripts/motion-specs.mjs`）

- `track(keys, tol = 0.004, from = 0)`：关键帧 → 按缓动采样成密点，再做 Douglas–Peucker 抽稀。
  首帧从 `from`（静止值）出发，否则预备动作会被吃掉。
- 缓动表：`lin / io / out / in / sine / back / snap`。`back` 用来做过冲，`snap` 用在"被戳到"的瞬间。
- `settle()`：对会回到静止的通道自动补「冲过 → 回弹 10% → 收尾」。参数值域下界为 0 的（嘴、眉、腮）
  不下冲，避免负数。
- 13 个动作：`nod shake tilt bow look_around yawn surprise angry sleepy hop pat_shy peek pout`。
  fadeIn 0.12 / fadeOut 0.38（原厂是 0.2 / 0.3，切过去会"闪"）。

## 四、触发：归一化 → 门控 → 执行 → 广播

参考：[桌宠点击反应四段式管道](https://jishuzhan.net/article/2111754901185650690)、
[Soullink Emotion SDK](https://github.com/nanlingyin/soullink-emotion-sdk)（分层混合、ownership）、
[CocoPet](https://github.com/ZDreamPY/CocoPet)（系统状态当触发源）。

`src/renderer/src/triggers.ts`：

1. **归一化**：所有输入先变成 `区域:tap|hold|rapid` / `drag:start|end` / `hover:Head|Body` /
   `system:idle|sleepy|lock|unlock|focus|blur` / `chat:error|done` / `clock:morning|late`。
2. **门控**（纯函数，只读）：勿扰 → 忙碌 → 冷却 → 查表。三条硬规则：
   - **用户亲手点的永远优先**。动作正在演也接 —— 否则"摸完头戳不动"就像卡死。
   - 忙碌只挡环境动作（闲时、时钟）。
   - 冷却按 **动作键** 算，不按区域；摸头 350 ms、连戳 2.6 s、锁屏 5 s。
3. **执行器故意做笨**：`behaviour.perform(action)`，只有 `face / gesture / group / hand / impulse`
   五种原语，不节流、不仲裁。
4. **广播**：`onEvent` 把 `{key, at, detail}` 抛给订阅方（现在是统计，以后接亲密度）。

`src/renderer/src/behaviour.ts` 因此退化成纯执行层：会播、会计"忙到什么时候"（时长取自
`manifest.motions[].duration`，不再拍脑袋估 2.2s）。

### 现在的触发源

| 源 | 事件 | 反应 |
|---|---|---|
| 指针 | 摸头 / 戳身体 | 脸红+抬手 / 滴汗+抖 |
| 指针 | 连戳 3 下 | 屑屑眼 + angry |
| 指针 | 按住 420 ms | 乖乖被摸（blush + pat_shy） |
| 指针 | 悬停 1.3 s | 探头看你 / 歪头 |
| 拖拽 | 拎起 / 放下 | 惊讶 + 头发甩 / 落地 hop |
| 系统 | 锁屏 / 解锁 | 睡 / 醒+伸展 |
| 系统 | 3 min 无输入 / 空闲 75 s | 犯困打哈欠 / 自己找事做 |
| 对话 | 出错 / 说完 | 圈圈眼 / 轻微甩发 |
| 时钟 | 6–10 点 / 23 点后 | 伸展 / 打哈欠 |

## 五、待机为什么像雕像，以及补上的「生命层」

动作再顺，只要**不演动作的时候她是不动的**，看上去就是一张会眨都不会眨的图。查了原厂 `motions/idle.motion3.json`：
Duration 5.983 循环，21 条曲线全是 `ShockL/ShockR/Param11/SweatBurst1-4/Divider22/Param27-32/Param55-58/Startwinkle`
—— **没有任何 `Angle*` / `Position*`，也没有 `ParamEyeLOpen/ROpen`**。所以待机只有物理在甩头发，身体、呼吸、眨眼全是零。

`src/renderer/src/alive.ts` 就是补这三件最小的事（全部程序化，不占 motion 文件）：

| 通道 | 做法 | 依据 |
|---|---|---|
| 呼吸 | 正弦，周期 3.8 s，**每圈 ±8% 随机换周期**（定周期像节拍器）；`PositionY` 0.55 + `ParamBreath` 0.55 反相配合 | 官方 Breath 组件就是 Offset/Peak/Cycle/Weight 的正弦 |
| 重心微晃 | `AngleZ` = 9.7 s + 4.13 s 两条非整数倍正弦；`PositionX` 12.4 s；`PositionZ` 15.3 s | 官方技巧第 1、6 条（张弛、永远不完全静止） |
| 眨眼 | 间隔 **2.5 s ± 2.0 s**（= 0.5–4.5 s 均匀随机）；闭 90 ms / 停 30 ms / 睁 150 ms，睁眼带 3.7% 过冲；12% 连眨两下；右眼晚 22 ms | 官方自动眨眼组件 `Mean=2.5 / Maximum Deviation=2.0`，文档原话「周期均匀会不自然」 |

**让位（ownership）**：官方《对各部位执行不同的动态管理》说得很直白 —— 多个管理器"后执行覆盖先执行"，
必须事先约定谁负责哪些参数，否则改到死。这里的约定是：

| 谁 | 独占参数 |
|---|---|
| `gaze.ts` 视线 | `ParamAngleX/Y`、`AngleX/AngleY`、`ParamEyeBallX/Y` |
| `alive.ts` 生命层 | `AngleZ`、`PositionX/Y/Z`、`ParamBreath`、`ParamEyeLOpen/ROpen` |
| `behaviour.ts` 动作 | 一切 motion（播放期间上面两层让位） |
| 表情 exp3 | `key1..13`、`Clothes1..5`、`LeanInput` |

两个必须记住的细节：

1. **让位是"立刻归位"，不是淡出**。motion 的 `FadeInTime` 只有 0.12 s，这层如果还以权重 1 写 0.5 s，
   动作开头会被压回中位，**刚做好的预备动作直接消失**。
2. **归位值不是 0**。眼睛的中位是 **1**（睁眼），写 0 等于把她按成闭眼 —— 第一版就这么干过，
   自检里 `ParamEyeLOpen=0.02` 才暴露出来。

**顺手加的一处**：人换注视目标时会顺手眨一下眼（Live2D 动画小技巧，也让"转头"有起点）。
`gaze.ts` 里目标方向跳变 > 0.38 且距上次 > 420 ms 时回调 `onSaccade` → `alive.blink()`，限流避免划鼠标时眨一片。

## 八、踩过的坑（别再踩）

1. **不要写 `ParamAngle*`**：它是物理占位，写它画面不动。转头写 `AngleX/AngleY/AngleZ`（变形器直接以它们为键）。
2. **不要写 `ParamBodyAngleRX/RY/RZ`**：看着能挪动整个人，但原厂 8 个动作一条都没用过 —— 那是物理输出通道。
3. **手部开关 `Param59–62` 不能手写**：引擎状态机会在 ~700 ms 把手拉回去，抬手只能用原厂 `TapBody#0/#1` 串。
4. **`getMotions()` 的 `name` 是 `组_序号`**（`Gesture_3`），不是动作名。按名字找动作必须用
   `manifest.motions` 的 id（`behaviour.ts` 里的 `idOf`），否则所有手势都会静默退化成随机。
5. **`TapBody` 组不能单独随机播**：里面是「抬手→放下」两段开关，随机播一段手会停在半空。
6. **两处去重 = 隐形丢事件**：main.ts 原来有自己的 250 ms 去重，把「三连戳」直接掐死在门控之前。
   去重/冷却只能有一处。
7. **`LeanInput` 是 `expr_lean` 独占的**（Add −30）。生命层一开始拿它做"前后慢漂"，结果每帧覆盖，
   把那个表情整个抹掉 —— 换成没有任何表情引用的 `PositionZ`。
8. **归位别写 0**：`ParamEyeLOpen` 中位是 1，写 0 是闭眼；归位要按参数各自的 HOME 值走。
9. **自检前先确认没有残留实例**：单实例锁会让新进程直接退出（表现是"启动即退、无任何渲染日志"），
   杀掉旧的 `electron.exe` 再跑。

## 九、服务器把「内心戏」当正文吐出来（已修）

接远程 AstrBot 后第一件事就撞上：模型把推理过程塞进 `plain` 流，中英文都有。

```
User says hi. Simple greeting, keep in character, short.

It's 2:21 AM. 本鲸在呢。
```

想到的第一版办法是「遇 CJK 才开始算正文」——**不可靠**：模型会用中文写推理、还会引用用户原话
（`用户是desktop_pet，私聊。简单打招呼。`），只要它先用中文自述就给骗过去了。

真正的解在事件里：同一条回复的 **`complete` 事件的 `data` 是干净全文**，不含推理。
所以适配器改成「**等流结束，用 complete 的文本，自己逐字喂给气泡**」：

- `streamed` / `clean` 两个缓冲；结束时 `const text = (clean || stripLeadingReasoning(streamed)).trim()`。
- 逐字节奏按长度分档：`>140 字 → 6 ms/字`，`>60 → 9`，其余 `14`。
- 代价：首字延迟从 ~1.1 s 涨到 ~1.7 s（等 complete）。换来的是**永远看不到内心戏**——对她来说值得。

顺带修了第二个坑：远程延迟下按 `Esc`，服务端已出队的 delta 还会继续到，文字边停边涨。
`bubble.ts` 加了 `muted` 闸，`interrupt()` 先置位再发 IPC，delta/segment/done 一律丢弃。

## 十、触发不止「点」：从她自己的台词推断

`[[act:nod]]` 这种标记协议要求模型配合输出，远程 AstrBot 的人格提示词不动，就只能读到纯正文。
所以加了**反向**的一条路：**从她说出来的话里猜她该做什么动作**。

`inferReactions(text, max = 2)` 是一张有序规则表（先匹配先得，每轮最多 2 条）：

| 她的台词命中 | 动作 |
|---|---|
| 哈哈 / 嘿嘿 / 笑死 / 好耶 | laugh |
| 呜呜 / 委屈 / 伤心 | cry |
| 害羞 / 脸红 / 不许看 | shy（脸红 + 低头） |
| 哼 / 生气 / 不理你 | angry（鼓腮 + 别脸） |
| 喜欢 / 想你 / 抱抱 | love |
| 困 / 晚安 / 去睡 / 熬夜 | sleepy（打哈欠 + 垂头） |
| 诶？/ 竟然 / 吓我 | surprise |
| 偷偷 / 瞄一眼 / 探头 | peek |
| 才不 / 不是啦 | shake |
| 以「嗯 / 对 / 是的」开头 | nod |
| 什么？/ 为啥 / 听不懂 | confused |
| 以问号结尾 | tilt |

三条约束，跟手势一样的纪律：

1. **走同一个门控**：1500 ms 冷却、每轮 ≤2 次，避免一句话甩出四个动作像抽风。
2. **冷却跨回复保持**（`beginReply()` 只清本轮计数，不清冷却）——否则连续两条回复都以「嗯」开头，她会连点两次头。
3. **只读正文、不碰大脑**：人格提示词、服务器配置一行没改（用户明确要求）。

实测（`PET_SEMCHECK=1` **13 项 0 失败**）+ 真机：她说「嗯，就这一句：主人，你今晚到底怎么了？」→ 打出
`[sem] 台词推断：nod`，接着真的点了一下头。

## 十一、没人理她的时候：主动开口

到这为止，她所有反应都是「被触发」的——点她、戳她、拖她、和她说话。真人不会这样：
安静久了会自己冒一句。补上这一层的文件是 `src/renderer/src/proactive.ts`。

**为什么台词走本地库、不走大脑**：远程 AstrBot 一次对话要 1.7 s 才出首字，而且"她一个人待着"这件事
不需要模型重新推理一遍；更关键的是**不能在她没说话的时候花掉一次上下文**。所以台词是本地写好的，
带 `[[act:…]]` 标记，交给语义层那套已有映射去演动作。

**四个时段 + 打瞌睡**：早上（5–11）/ 白天（11–17）/ 傍晚（17–23）/ 深夜（23–5）各 4 句，
超过 10 分钟没动静切到「打瞌睡」池。台词本身就是角色感的一部分：

- 深夜：「主人，再不睡我要生气了。」`[[act:angry]]`
- 白天：「……我就看看你在不在。」`[[act:peek]]`
- 打瞌睡：「……（她好像靠着睡着了）」`[[act:sleepy]]`

**三条纪律**（和触发层、语义层完全同构）：

1. **只在安静时说**：勿扰、气泡开着、正在演动作 —— 一律不说（`isQuiet` / `isBusy`）。
2. **说出来才计时**：`say()` 返回 false（气泡接不住）就 30 s 后重试，**不吞掉这一句**。
3. **说完退避**：下一次至少 4 分钟（首次等待 2–3.5 分钟，都带随机抖动，避免像定时器）。
   用户任何一次点击 / 拖动 / 聊天都会把时钟拨回起点（`notifyActivity()`）。

**一处必须记住的实现细节**：气泡的 `say()` 到点收起时，先 `setText('')` 再 `setBubble.hidden = true`。
反过来写会被 `setText` 里的 `bubble.hidden = false` 重新点亮——表现为"文字清空了，但那个空泡泡一直挂着"。

**验收**：`PET_PROCHECK=1` **10 项 0 失败**（前十秒不开口 / 到点说 / 标记已剥离 / 带了动作 / 说完退避 /
活动后重新计时 / 勿扰闭嘴且不消耗 / 接不住时重试 / 凌晨换台词 / 关掉后静音）。
气泡这条链路用 `PET_SAY='…'` 自证：显示时 `hidden=false text="…"`，1.2 s 后 `hidden=true text=""`。
