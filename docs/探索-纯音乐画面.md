# 探索：纯音乐时那半屏放什么

> 记录 2026-11-12 这一轮的四个方向、真实截图、为什么放弃，以及现在的结论。
> 现在线上跑的是第四节「用歌词 PV 演歌曲信息」，前三节都停用但代码留着。

## 背景

唱片机卡片是竖的 380×600 起步。有歌词的歌交给 JIZURA 的歌词 PV（`app/pv.mjs`）。
纯音乐没有歌词，中间会出现一大块空白（约 557×310），一开始想用「数据可视化」填。

用户对这块的期望，前后明确了三次：

1. 「不要频谱那种，要**类似代码动画、不断变化**的动效」（m11609）
2. 「生成式的流体/粒子，**还要会出现组合图案或物体**，参考 CatMusicFree 那种粒子+毛玻璃」（m11641）
3. 「现在的还是不好看，而且**太单一，纯线条感觉不够**」（m11735）
4. 最后定：「**先不做单纯的动效了**，纯音乐就用 pv-tool / JIZURA 的模板反复播放歌曲信息；单纯动效以后再单独研究」（m11757/m11764）

## 四个方向（按时间顺序）

### v1 环形频谱 + 尘埃（已停用）

- 做法：环形频谱贴唱片外缘、中心光晕、低频浮尘、底部水位线；有词时隐藏底部条形频谱。
- 判纯音乐用 `isInstrumental()`：网易云对无词曲目返回单条「纯音乐，请欣赏」，不能只看 `lines.length`。
- 封面取色 `coverHue()`：缩到 12×12、取饱和度最高的像素转 hue。
- 截图：`_probe/viz-instrumental.png`。
- 放弃原因：这是「数据仪表盘」，不是「画面」。用户要的是会自己演的东西。

### v2 流场粒子 + 软体团 + 几何纹样（已停用）

- 做法：460 个粒子走两层正弦流场、3 个软体团 lissajous 漂移、5 种纹样每 18s 轮换、曲名闪现。
- 截图：`_probe/gen-0.png`（洋红大光斑 + 满屏网格，盖住唱片，构图糊）。
- 放弃原因：色团太大太亮，盖住唱片与标题；元素各演各的，没有主次。

### v3 三种模式（星云光团 / 粒子星座 / 几何构成）

都写进了 `app/viz.mjs`，用 `window.__vizMode('nebula'|'constellation'|'geo')` 切换，截图 `_probe/mode-*.png`。

| 模式 | 做法 | 问题 |
|---|---|---|
| `nebula` | 两层大面积柔光底 + 3 个呼吸光团 + 结构环 + 星点 + 节拍涟漪 + 地平线 + 上下左右羽化 | 有体积了，但一屏只有「一团光 + 一个环」，看十秒就腻 |
| `constellation` | 90 个节点漂移、距离小于 90–130px 连白线、节点带光晕 | 更像「星空壁纸」，与歌没关系 |
| `geo` | 7 个大色块（矩形/圆/三角）平移旋转、`lighter` 混合 + 半调网点 | 版式感强，但和唱片机界面打架 |

关键实现细节（以后要复用就抄这些）：

- 只画在 `clip` 区域里（`#pvDots` 下沿到 `#prog` 上沿），永远不遮挡唱片、标题、控件；
- 上下左右用 `destination-out` 渐变**羽化**，否则会出现一条硬接缝；
- 节拍用 `bass - prevBass > 0.14` 自适应检测，比外部传 beat 稳；
- 画布像素尺寸**只能由场景自己设一次**——`vizResize()` 再设一次 canvas.width 会把 2D 上下文复位，画面直接全黑（踩过）；
- `clip.w` 要用 `scene.size.w`，不是场景对象上的 `viz.w`（踩过，裁剪区为空 → 什么都不画）。

### v4 结论：纯音乐交给歌词 PV，反复演歌曲信息

- `app/player.js` 的 `infoLines(song, dur)`：把「歌名 / 歌手」当成 LRC 行，每 6 秒一行、循环铺满整首（`[{t: 400, text: '歌名'}, {t: 6400, text: '歌手'}, …]`）。
- 然后走与有词歌曲完全相同的路径：`pv.setLyrics(...)` + `pv.draw(audio.currentTime)`。
- 好处：模板、配色、节拍对齐、出场/退场全用 JIZURA 那 1,700 个部品，不额外写动效代码。
- 截图：`_probe/gen-1.png`（`Kuschelklassik Piano Dreams, Vol. 2` 以报纸体演出来）。

## 踩过的两个真 bug（PV 侧）

1. **`bootPv()` 里 `if (lines.length) pv.setLyrics(lines)` 会清掉刚设好的信息行**：动态 import 是异步的，`await bootPv()` 之前拿到的是旧的 `lines`（网易云那条「纯音乐，请欣赏」），一进去就把 33 行信息替换成 1 行。改法：`bootPv()` 返回同一个 promise，调用方 `await`，并删掉那句提前 `setLyrics`。
2. **`loadLyric()` 里 `setInfo()` 太早**：同上，等 `await bootPv()` 之后再设。

## 仍然有效的东西

- `app/viz.mjs` 整套留着（含三种模式与 `__vizMode`），只是 `setVizOn(false)` 不再启用——以后单独研究动效时直接拿它当沙盒。
- pv-tool（PixiJS + GSAP，16 模板 / 54 效果，79 个 effect 模块）和 `D:\pv文字预设`（100 套剪映草稿）都只当**参考**：
  - pv-tool 的许可是 Non-Commercial，且明确禁止 embed/bundle 进产品 ⇒ 不能搬代码；
  - 剪映预设的 Readme 允许学习/修改/分享，禁止销售预设本身 ⇒ 只能看动画，不能打包分发。

## 下一步（未做）

- 给纯音乐再加 2–3 套「信息模板」：现在只有「歌名 → 歌手」两行轮播，可以让它「歌名大字 → 歌手小字 → 空拍」有节奏，或按 BPM 决定每行停多久。
- 让 `[[pv:模板名]]` 由她指定纯音乐用哪套。
